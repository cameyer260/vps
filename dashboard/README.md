# dashboard

Web application for managing pi agents ("jarvis" containers) running on my VPS, with a ChatGPT-like chat UI, an Obsidian-like notes viewer/editor, and agent lifecycle management. Hosted on the VPS, accessed via Cloudflare tunnel, run in Docker.

Read the [root README](../README.md) first — it has the essential context on the VPS setup and how jarvis runs agents, which this application is designed around.

## Phase 9: Build the notes/admin dashboard

What I Want:

- Web application that will run on localhost on the VPS and receive requests from Cloudflare tunneling. It needs to run in a Docker container.
- 1. A coherent dashboard to manage agents from. Each agent will be an instance of Jarvis (pi inside a container, using Openrouter provider for models). I should see a list of my agents currently active and their status (running/working, waiting on reply/done, etc). I should be able to terminate and start new agents; starting new agents will just run Jarvis on whatever project I specify (which should autocreate it if the project does not yet exist and that should include initializing git). The project could be a research task I want AI to dig into and take notes on for me or it could just be a regular software project.
- 2. Clicking an active agent or starting a new one (after choosing on what project to run and other config settings if applicable) should enter you into a UI interface of the chat with that model. On the VPS that is just jarvis (pi running in the container) but on my phone I don't want it to be a terminal pi instance, I want it to look like a nice ChatGPT-like UI. *So I need to figure out how to accomplish this.* Read/watch pi session history files? Stream straight from pi instance? Need to figure out a way to relay it real time and communicate with pi instance for this to work.
- 3. I should be able to pickup old pi sessions/conversations on new agent instances. When starting a new agent I should be able to pick a conversation to pickup from. On a new project there will be none, on existing projects there may or may not be some.
- 4. There should always be an agent running on my notes and I need a non-edit/chat-only mode that I can toggle on and off on this one. I should be able to, within one click, open this agent which will be pi but on my notes project. Anytime I enter this it should git pull (and surface any errors to the user so I can decide how to handle by taking agent off read only and having it fix). This agent will be used for general chat only purposes as well as actually writing to my notes dir and making note of things. The idea here is that I want ChatGPT on the go; I want an AI chatbot that I can ask questions on the go like I would ChatGPT, but I also want the ability to decide to make note of something we are talking about or read or edit some notes I have from earlier. This will allow me to perform much better on the go research because it allows me to make note of things and talk to an agent with access to those notes. So this will be my version of ChatGPT but with context to a notes dir.
- 5. I need an Obsidian clone so I can open my notes dir to read and edit files. Really just copying Obsidian here for the UI; though because I am runnin it on a repo, it does need to git pull on open (and surface any errors to the user which I can copy to clipboard so I can have agent look at it and fix), and I need a save button (as well as a read/edit toggle just like the Obsidian button) which will commit and push under the hood.
- 6. Future improvement will be to also make a simple IDE. Could literally just expand my Obsidian clone for the notes to do this; pretty much the same functionality except this would need to support more file formats. This will be for coding projects and mostly for me to just look at the files and not for editing.
- 7. Another future improvement will be that I can have a voice/talking mode for the notes agent. Like where I can talk back and forth while remaining control to still choose to talk to an intelligent model and just deal with any delay there is. It doesn't have to be perfect in the start and actually really shouldn't be. I literally just need a button to click when I talk and click off when I'm done and want my response (which I can click while the AI is responding and it will just interrupt it). So the main engineering here is just getting a good speech recognition to run (could start off using apples built it though it kind sucks will prob want to look for alternatives) and good text to speech (so the AI response can actually be said out loud by a voice rather than remaining text on a screen).
